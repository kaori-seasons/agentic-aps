# 第七章：生产落地与系统演进——从可用原型到稳定平台

## 总论：能算出结果，不等于系统已经准备好进入工厂

排产系统最容易出现一种错觉：

> 样例数据能跑通一次排产，所以系统已经可以上线。

实际上，生产落地至少还要回答四个问题：

1. **求解过程是否可追踪？**
2. **求解结果是否可校验、可回退、可确认？**
3. **大批量数据进入后是否还能保持可用？**
4. **系统是否支持持续演进，而不是一版写死？**

从当前仓库来看，JVS-APS 已经具备不少“平台化”特征，但也仍有明确的进化空间。

---

## 一、当前系统已经具备的生产化特征

### 1.1 异步求解与进度管理

`SolveServiceImpl.solve(...)` 使用异步执行，并通过 Redis 缓存当前求解任务 ID，同时由 `SolveProgressService` 维护进度状态。

这意味着系统已经意识到：

- 排产不是瞬时操作
- 前端不能阻塞等待
- 过程必须可见、可取消

### 1.2 结果校验与异常处理

求解完成后，系统还会：

- 检查 `initScore` 与 `hardScore`
- 校验任务合规性
- 对失败写入进度日志

这说明当前系统并不是“有结果就保存”，而是至少有一层结果质量闸门。

### 1.3 前后端闭环已经打通

从前端菜单和后端控制器来看，系统已经形成完整业务闭环：

```
主数据维护
   ↓
工艺与日历维护
   ↓
策略配置
   ↓
发起排产
   ↓
查看进度
   ↓
预览甘特图
   ↓
人工调整
   ↓
确认计划
```

这比单纯的“算法 Demo”成熟得多。

---

## 二、当前落地时最值得关注的三类风险

### 2.1 基础数据不完整

APS 的最大隐患不是算法错误，而是数据空洞。

典型问题包括：

- 工艺路线缺失
- 资源能力配置不准
- 工作日历与现场班次不一致
- BOM 深度不完整

一旦这些数据失真，系统排出的计划会呈现“逻辑正确但现场无法执行”的假象。

### 2.2 策略配置失真

当前系统已经开放了较多策略参数，这是一把双刃剑：

- 好处是灵活
- 风险是业务方可能不理解权重含义

如果把某个权重调得过高，可能出现：

- 过度集中高优先级任务
- 资源利用率下降
- 换型成本优化压倒交期目标

### 2.3 大规模数据下的交互与性能压力

从前端实现可以看出，资源甘特图已经承载大量互动操作。随着：

- 资源数增多
- 任务数增多
- 时间轴跨度增大

前端渲染、后端报表生成、求解耗时都会同步增加。

## 三、建议的生产治理体系

### 3.1 策略治理

建议企业在正式上线时不要只保留一套策略，而是至少维护三套模板：

| 模板 | 用途 |
|------|------|
| 标准模板 | 日常排产 |
| 交期优先模板 | 插单或交期压力期 |
| 稳定模板 | 结果更保守，便于业务验收 |

### 3.2 数据治理

建议把以下数据纳入上线前检查清单：

1. 生产订单是否都可排
2. 工艺路线是否闭环
3. 主资源是否绑定日历
4. 关键工序是否配置可用资源
5. 补充订单生成逻辑是否稳定

### 3.3 运行治理

建议重点监控三类运行指标：

| 类别 | 指标 |
|------|------|
| 求解过程 | 排产耗时、是否提前终止、是否找到可行解 |
| 结果质量 | 逾期任务数、资源冲突数、任务合规率 |
| 用户行为 | 调整频次、锁定任务数量、计划放弃率 |

这些指标不是“锦上添花”，而是判断 APS 是否真正被业务接受的核心证据。

## 四、后续演进的四个方向

### 4.1 求解器服务独立化

当前系统已经具备异步求解能力，下一步很自然的演进方向是：

- 将求解能力独立部署为 Worker
- 管理层负责接单与结果回传
- 重型求解和普通 CRUD 服务隔离

### 4.2 更细粒度的行业模板

当前系统已有：

- `DEFAULT`
- `FFD_TABU`
- `FFD_LATE_ACCEPTANCE`

未来可以继续向行业模板演进，例如：

- 交期型模板
- 换型型模板
- 均衡型模板

### 4.3 更完整的约束体系

当前系统已经覆盖 APS 的主干约束，但后续仍可继续加强：

- 人员能力约束
- 更复杂的物料齐套约束
- 多资源同步约束
- 更精细的 setup matrix

### 4.4 更强的仿真与复盘能力

成熟 APS 平台最终都需要回答一个问题：

> 如果我换一套策略，结果会怎样？

这就需要逐步增强：

- 场景回放
- 策略对比
- 历史快照复现
- 固定随机种子的实验能力

而当前系统其实已经为此埋下了基础，例如策略模板、随机种子、待确认计划等设计。

## 五、全书总结

到这里，这套系列文章已经把 JVS-APS 当前系统的主干逻辑串了起来：

```
业务问题
   ↓
领域建模
   ↓
求解器装配
   ↓
时间推导
   ↓
约束评分
   ↓
甘特协同
   ↓
生产治理
```

如果只用一句话概括当前系统，可以说：

**JVS-APS 已经不是一个单点排程算法，而是一套以 OptaPlanner 为求解核心、以甘特图为交互核心、以策略配置为治理核心的制造排产平台雏形。**

## 六、本章总结

### 核心结论

1. **当前系统已经具备较强的生产化基础。**
2. **真正的上线难点主要来自数据治理、策略治理和规模治理。**
3. **未来的竞争力不只在算法，更在平台化能力。**

### 关键数字

- 当前显式求解模板：3 个
- 结果展示主视角：3 类
- 任务调整主能力：5 组
- 系列文章总章节：7 章

### 最终收束

这套书稿的目的，不是把 JVS-APS 描述成“已经完美”，而是把它解释成“为什么现在能工作、工作边界在哪里、下一步如何继续长成一套更成熟的 APS 平台”。这也是当前系统最有价值的地方。
