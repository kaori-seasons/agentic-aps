# 排产员端到端傻瓜式操作手册

适用角色：`APS_SCHEDULER`

你是“把计划跑出来并调顺”的角色，不是主数据治理 owner，也不是最终确认人。当前代码里，你可以发起排产、看预览、做人工调整、派工、报工，但**你不能确认正式计划，也不能维护排产策略有效性之外的审批职责。**

## 1. 你今天要完成什么

1. 根据计划主管给出的策略或排产要求，跑出一版候选计划。
2. 用甘特图把明显不合理的任务顺序、时间冲突、任务颗粒度修顺。
3. 把候选结果交给计划主管确认。
4. 执行中协助派工、回收报工数据。

## 2. 你能看到哪些菜单，不能做什么

你能看到：

| 菜单 | 你能做什么 |
| --- | --- |
| 物料、主资源、生产订单、来料计划、制造BOM、工艺、工艺路线、生产日历 | 主要用于查看，帮助判断问题来源 |
| 排产策略 | 只能查看 |
| 排产计划 | 生成、预览、放弃、人工调整、派工、报工 |

你做不了：

| 事项 | 原因 |
| --- | --- |
| 确认正式计划 | 没有 `aps:schedule:confirm` 权限 |
| 查看操作审计 | 没有 `aps:audit:view` 权限 |
| 修改报工字段参数设置 | 没有 `aps:report-field:edit` 权限 |

## 3. 先记住三条工作原则

### 3.1 你负责把候选结果调顺，不负责替代主管背书

你可以调得更合理，但不能擅自把结果当正式计划确认下去。

### 3.2 少量人工调整是正常的，大量人工调整说明前面就错了

如果你发现每次都要移动一大片任务，问题多半在策略、工艺路线、资源日历或订单优先级，而不是你的拖拽技巧不够。

### 3.3 当前版本没有工艺路线 Excel 导入

如果你发现结果不合理且根因在工艺路线，正确动作是通知计划主管/主数据维护人去页面修，或转实施开发做批量导入，不是你去系统里找隐藏按钮。

## 4. 每天开工后的固定动作

1. 打开 `排产计划`
2. 看顶部状态卡片是否仍有上一次排产进度
3. 如果状态是 `SCHEDULING`，不要重复发起
4. 如果状态是 `SUCCESS`，先确认这是不是今天要处理的那一版
5. 如果旧结果无效，和计划主管确认后再 `放弃`
6. 切到 `待排订单`，看今天关键订单是否都在列表中

## 5. 标准端到端流程

## 5.1 第一步：检查待排订单

页面：`排产计划` -> `待排订单`

你要重点看：

| 字段 | 你看它是为了什么 |
| --- | --- |
| 订单号 | 确认急单、插单是否已经进入系统 |
| 需求日期 | 判断交期紧迫度 |
| 优先级 | 判断排产顺序是否应该靠前 |
| 排产状态 | 判断订单当前是未排、已排、已完成还是无需排 |
| 可排开关 `canSchedule` | 判断订单是否被允许参与排产 |

按钮与结果：

| 你点击了什么 | 会发生什么 | 你如何判断 | 下一步 |
| --- | --- | --- | --- |
| `移动` | 调整订单相对顺序 | 适用于少量顺序修正 | 再发起排产 |
| `补充订单` | 打开补充订单弹窗 | 用于查看/补充相关订单 | 核查是否需要一并排 |
| `canSchedule` 开关 | 订单可参与或退出排产 | 只在你明确知道业务意图时再改 | 再重新排产 |

注意：当前代码在这个区域的权限控制偏粗，某些动作对仅有查看权限的角色也可能可见。你的岗位实践应保持克制，不要把它当成“谁都应该在这里改顺序”。

## 5.2 第二步：发起排产

页面：`排产计划`

操作：

1. 点击顶部 `生成排产`
2. 在策略弹窗中选择一条已有策略
3. 等待顶部卡片进入 `SCHEDULING`
4. 点击 `详情>` 看进度

结果判断：

| 状态 | 说明 | 你该怎么做 |
| --- | --- | --- |
| `SCHEDULING` | 正在求解 | 等待完成 |
| `SUCCESS` | 候选结果可看 | 立刻进入预览 |
| `NO_SCHEDULED` | 当前没有需要排的订单 | 回待排订单检查 |
| `FAILURE` | 数据或系统异常 | 先排查输入，再反馈计划主管/开发 |

## 5.3 第三步：预览并判断“这版值不值得调”

页面：进度弹窗 -> `预览`

先问自己三个问题：

1. 急单是否被排进去了。
2. 关键资源是否出现明显不合理的拥堵、空闲或来回切换。
3. 任务拆分是否已经细碎到现场无法执行。

如果三项都严重异常，不要急着做大量手工调整，先回头判断是不是策略或主数据就错了。

## 5.4 第四步：在资源甘特图里调顺

页面：`排产计划` -> `资源甘特图`

你能用的核心按钮：

| 按钮 | 用来解决什么问题 | 什么时候不该用 |
| --- | --- | --- |
| `拆分` | 一个任务过长，现场需要分批/分班执行 | 根因是工艺节拍错时 |
| `合并` | 多个碎片任务本应连续执行 | 根因是求解逻辑系统性异常时 |
| `移动` | 某任务必须换时段或让位急单 | 当大量任务都要搬家时 |
| `锁定` | 把关键任务固定住，避免后续重排丢失 | 还没想清楚最终方案时 |
| `解锁` | 释放不再需要固化的任务 | 明明现场已开工时 |
| `撤销` | 回退本轮人工调度 | 需要保留关键锁定时不要误用 |

建议的最小动作顺序：

1. 先移动急单相关任务
2. 再拆分超长任务
3. 再合并过碎任务
4. 最后只锁定必须保留的关键任务

这是因为锁定越早，后续重排空间越小。

## 5.5 第五步：和计划主管交接确认

你不能点 `提交` 让计划生效，所以你的标准交付不是“我调完了”，而是下面四句话：

1. 用了哪条策略。
2. 这版排产状态是 `SUCCESS`。
3. 你做了哪些人工调整。
4. 哪些任务已经锁定，为什么要锁。

这四项不说清楚，计划主管即使点了确认，也无法判断风险边界。

## 5.6 第六步：派工与报工协同

页面：`资源甘特图`

你可以做两类执行协同：

### 派工

1. 在甘特图确认任务顺序
2. 点击 `派工`
3. 导出或下发给现场执行

### 报工

1. 现场回传进度后，点击 `报工`
2. 如需修正某任务，打开任务详情
3. 填写 `实际完工时间`、`实际完成数量`
4. 合并任务场景下，可在 `子任务` 页签批量填报
5. 保存后刷新结果

## 6. 按钮级操作对照表

| 页面 | 按钮/动作 | 你会看到什么 | 说明什么 | 你接下来做什么 |
| --- | --- | --- | --- | --- |
| 待排订单 | `移动` | 打开移动弹窗 | 订单顺序可手工干预 | 调整后重排 |
| 待排订单 | `补充订单` | 打开相关订单列表 | 该订单还有补充关系 | 判断是否一并纳入 |
| 待排订单 | `canSchedule` | 订单可排状态切换 | 是否允许参与排产 | 变更后重新生成 |
| 排产计划顶部 | `生成排产` | 弹出策略列表 | 可以选择已有策略发起求解 | 选择策略 |
| 排产进度 | `详情>` | 打开进度明细 | 可判断当前状态 | 成功则预览 |
| 排产进度 | `预览` | 打开全屏预览 | 候选结果已生成 | 去甘特图修顺 |
| 排产进度 | `放弃` | 丢弃本轮结果 | 当前结果不能用 | 回到待排或策略沟通 |
| 资源甘特图 | `拆分` | 选择拆分方式 | 任务可细分 | 核查是否更易执行 |
| 资源甘特图 | `合并` | 确认合并 | 碎片任务可收敛 | 复核时长与顺序 |
| 资源甘特图 | `移动` | 打开移动面板 | 局部时间可人工修正 | 再次检查冲突 |
| 资源甘特图 | `锁定` | 任务锁住 | 后续重排将保留该约束 | 交接给主管 |
| 资源甘特图 | `派工` | 派工成功提示 | 可以下发车间 | 开始执行 |
| 资源甘特图 | `报工` | 打开报工入口 | 可以回写实际进度 | 维护完成数据 |

## 7. 异常处理表

| 现象 | 大概率根因 | 你自己能做什么 | 什么时候要转办 |
| --- | --- | --- | --- |
| 排产失败 | 主数据缺失、订单异常、后端报错 | 先核对待排订单、工艺路线、日历 | 后端异常或看不懂日志时转计划主管/开发 |
| 结果里急单没靠前 | 优先级或策略排序问题 | 先少量移动验证 | 持续出现时转计划主管调策略 |
| 同一资源上任务过碎 | 过度拆分或策略导致 | 合并局部任务 | 大面积出现时转计划主管复盘策略 |
| 任务根本排不进来 | 订单不可排、路线缺失、资源无班次 | 查 `canSchedule`、工艺路线、日历 | 无法补数据时转主数据责任人 |
| 现场要求按新工艺执行 | 系统路线已过时 | 不能在甘特图上假装解决 | 转主数据维护人修工艺路线 |
| 想从 Excel 导入工艺路线 | 当前产品不支持 | 无法自行处理 | 转实施/开发 |

## 8. 当前版本边界

1. 你可以查看策略，但默认不承担策略治理职责。
2. 你可以调整甘特图，但不应长期代替主数据修复。
3. 你可以派工和报工，但不能把候选结果直接确认为正式计划。
4. 当前版本没有面向你的工艺路线 Excel 导入通道。

如果你只记一句话，请记这句：**排产员的价值不在“把系统跑一遍”，而在用最少人工动作把候选计划修到可交付，并及时识别哪些问题根本不该靠人工调度解决。**
