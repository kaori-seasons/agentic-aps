# 计划主管端到端傻瓜式操作手册

适用角色：`APS_PLAN_MANAGER`

本文不是“理想中的 APS 流程”，而是基于当前代码与页面真实能力整理出来的生产可用 SOP。你在当前版本里可以做三类事：治理排产输入、发起并确认计划、追查异常与责任。你也要知道一件事：**系统不会替你修正错误主数据，排产器只会把错误主数据放大成错误计划。**

## 1. 你今天要完成什么

1. 确认今天参与排产的数据是否齐全且可信。
2. 选择一条有效排产策略，发起排产并看结果是否可执行。
3. 必要时在甘特图内做人工调整。
4. 最终确认一版正式计划，供车间执行。
5. 出现争议时，通过操作审计追查是谁改了什么。

## 2. 你能看到哪些菜单

你可以看到并操作以下菜单：

| 菜单 | 你能做什么 | 用途 |
| --- | --- | --- |
| 物料 | 查看、新增、编辑 | 维护产品与物料基础信息 |
| 主资源 | 查看、新增、编辑 | 维护产线、设备、班组等主资源 |
| 生产订单 | 查看、新增、编辑 | 维护待排产订单 |
| 来料计划 | 查看、新增、编辑 | 维护物料到货约束 |
| 制造BOM | 查看、新增、编辑 | 维护生产消耗结构 |
| 工艺 | 查看、新增、编辑 | 维护工序定义 |
| 工艺路线 | 查看、新增、编辑、启停 | 维护工序顺序与资源关系 |
| 生产日历 | 查看、新增、编辑、启停 | 维护工作日与时间段 |
| 排产策略 | 查看、新增、编辑、切换有效 | 维护求解方向与排序规则 |
| 排产计划 | 生成、预览、放弃、确认、人工调整、派工、报工 | 形成正式计划并闭环执行 |
| 操作审计 | 查看 | 追查关键操作 |

## 3. 先记住四条判断原则

### 3.1 先修输入，再修结果

如果错误来自订单、BOM、工艺路线、资源日历，优先回主数据页面修正；不要指望靠甘特图“拖一拖”把系统性错误掩盖掉。

### 3.2 预览阶段允许试错，确认阶段必须保守

排产成功后，先看预览，再决定是否确认。确认时系统会提示：**已锁定的任务调整会保留，未锁定的调整会被清空。** 所以确认前要明确哪些人工调整必须通过“锁定”固化。

### 3.3 有异常先判断“是算不出来”还是“算出来但不合理”

- `FAILURE`：通常是数据问题、约束冲突、后端异常。
- `NO_SCHEDULED`：当前无需排产，通常是没有可排订单或订单均被标记为不可排。
- `SUCCESS` 但结果难执行：通常不是系统挂了，而是排序规则、主数据或人工约束不合理。

### 3.4 当前版本没有“工艺路线 Excel 导入”

当前 UI 没有工艺路线、工艺、日历、BOM、订单的通用 Excel 导入入口。你看到的“导入”能力，真实存在且可用的主要是资源甘特图中的报工导入。  
如果业务要求批量导入工艺路线，请转交实施或开发，不要让一线人员在系统里盲找按钮。

## 4. 每天第一步从哪里点

### 4.1 排产前数据检查

按下面顺序点菜单检查：

1. 点 `生产订单`
2. 按需求日期、优先级检查今天要排的订单是否存在
3. 点 `来料计划`
4. 检查关键物料是否有到料时间
5. 点 `制造BOM`
6. 抽查高优先级订单对应产品的子件是否齐全
7. 点 `工艺`
8. 检查关键工序是否存在
9. 点 `工艺路线`
10. 检查关键产品是否已有启用中的工艺路线
11. 点 `生产日历`
12. 检查主资源在排产时段是否有工作时间
13. 点 `排产策略`
14. 确认至少有一条策略被标记为“是否有效”

### 4.2 哪些现象说明你不该直接排产

| 现象 | 说明 | 正确动作 |
| --- | --- | --- |
| 订单有数量，但没有可用工艺路线 | 求解器没有加工路径 | 先补工艺/工艺路线 |
| 工艺路线有工序，但资源日历没开班 | 有路径但没产能时间 | 先补生产日历 |
| BOM 缺子件 | 物料需求计算不可信 | 先补 BOM |
| 来料计划为空且策略启用物料约束 | 很可能排不出或排得过于保守 | 先补来料计划，或临时调整策略 |
| 策略没有激活 | 生成排产时无有效策略上下文 | 先去策略页启用一条 |

## 5. 标准端到端流程

## 5.1 第一步：确认策略

页面：`排产策略`

操作：

1. 打开 `排产策略`
2. 看列表中的“是否有效”
3. 如果没有有效策略，点击 `新增`
4. 填写 `策略名称`、`开始时间`、`排产方向`
5. 按需要配置 `无改进时长(秒)`、`约束物料`、`排产规则`
6. 保存后，在列表中点击“是否有效”开关，使其生效

结果判断：

| 你点击了什么 | 看到什么 | 说明什么 | 下一步 |
| --- | --- | --- | --- |
| `新增` | 弹出策略表单 | 你可以配置本次求解逻辑 | 填完并保存 |
| 有效开关 | 行上出现选中态 | 该策略会作为当前有效策略 | 去排产计划 |
| 编辑 | 弹出已有策略 | 可以微调排序规则 | 修改后再排产 |

经验判断：

- 订单交期普遍紧张时，优先检查是否该用逆排。
- 如果结果总是优先照顾低价值订单，先检查排产规则中的优先级字段排序。
- 如果缺料场景很多，且现场又不允许“先排后补料”，应打开 `约束物料`。

## 5.2 第二步：发起排产

页面：`排产计划`

操作：

1. 点 `排产计划`
2. 页面顶部会有一个大卡片
3. 如果顶部显示 `生成排产`，点击该卡片
4. 在弹窗中点击一条策略
5. 系统开始排产，顶部卡片会显示进度
6. 点 `详情>` 打开进度窗口

结果判断：

| 状态 | 业务含义 | 你该怎么做 |
| --- | --- | --- |
| `SCHEDULING` 排程中 | 求解器正在跑 | 等待，不要重复发起 |
| `SUCCESS` 排程成功 | 生成了一版候选结果 | 先预览，再决定是否确认 |
| `NO_SCHEDULED` 无需排程 | 当前没有需要排的订单 | 去待排订单核查订单状态与可排开关 |
| `FAILURE` 排程失败 | 数据、约束或服务异常 | 看进度明细，按异常表处理 |
| `NONE` 暂无排程进度 | 当前没有运行中的任务 | 可重新发起排产 |

## 5.3 第三步：预览结果，不急着确认

页面：`排产计划` -> 进度弹窗 -> `预览`

操作：

1. 当状态为 `SUCCESS` 时，点击 `预览`
2. 重点看 `资源甘特图`、`订单甘特图`、`物料需求甘特图`、`计划任务`
3. 判断这版计划是不是“能落地执行”

建议你按以下顺序看：

1. 先看 `待排订单`
2. 再看 `资源甘特图`
3. 再看 `计划任务`
4. 最后看 `物料需求甘特图`

这是第一性原理上的最小闭环：先看有没有单没进计划，再看资源是否超挤，再看任务拆分是否怪异，最后看物料是否跟得上。

## 5.4 第四步：人工调整

页面：`排产计划` -> `资源甘特图`

你可用的按钮有：`撤销`、`拆分`、`合并`、`移动`、`锁定`、`解锁`、`报工`、`派工`、`参数设置`

常用调整方法：

| 场景 | 应该点什么 | 结果 | 何时使用 |
| --- | --- | --- | --- |
| 一个任务太大，现场要拆班执行 | `拆分` | 把任务拆成多个任务 | 长任务跨班次、跨设备时 |
| 两个碎片任务应连续加工 | `合并` | 合并为一个较大任务 | 避免切换损失时 |
| 某任务必须换到别的时间 | `移动` | 手动指定开始时间或移位 | 设备保养、急单插单时 |
| 某任务绝不能再被系统改动 | `锁定` | 任务被标记锁定 | 已派工或已承诺现场时 |
| 误调了任务 | `撤销` | 撤回移动、拆分、合并 | 回到调整前状态 |

关键判断：

- 如果你发现很多任务都要手工移动，说明不是“这版计划差一点”，而是主数据或策略有系统性问题，应回头修策略或输入数据。
- 锁定只该用于“必须保留”的任务，不要把整条产线全锁死，否则下一次重排会失去优化空间。

## 5.5 第五步：确认正式计划

页面：`排产计划` -> 进度弹窗 -> `提交`

操作：

1. 预览与人工调整完成后，回到进度详情
2. 点击 `提交`
3. 如果系统弹出“若有调整，锁定的任务调整将生效，未锁定的任务将被清空。是否继续？”
4. 再次确认确实只保留锁定调整
5. 点击确认

结果判断：

| 结果 | 说明 | 下一步 |
| --- | --- | --- |
| 提交成功 | 这版计划成为正式结果 | 通知排产员/调度员开始执行与反馈 |
| 提交后发现某些人工调整没保留 | 这些调整之前没有锁定 | 重新评估是否需要再次调整并锁定后重排/重提 |

## 5.6 第六步：派工与执行闭环

页面：`资源甘特图`

操作：

1. 选择需要下发的任务或时间范围
2. 点 `派工`
3. 将派工结果提供给现场
4. 执行过程中，如现场回传实际完工时间、实际完成数量，点 `报工`
5. 必要时打开任务详情，直接修正 `实际完工时间`、`实际完成数量`

你要盯住的不是“系统里有数据”，而是“系统里的进度是否正在把现场事实回写回来”。如果计划不吸收真实进度，下一轮排产一定会失真。

## 5.7 第七步：审计与追责

页面：`操作审计`

当出现“计划被改乱了”“谁取消了排产”“谁调整了关键数据”等问题时：

1. 打开 `操作审计`
2. 按 `用户名`、`操作名称`、`权限编码`、`成功/失败`、`URI`、`创建时间` 搜索
3. 锁定具体操作记录
4. 区分是误操作、流程问题还是权限设计问题

## 6. 按钮级操作对照表

| 页面 | 按钮/动作 | 你会看到什么 | 你应该怎么判断 | 下一步 |
| --- | --- | --- | --- | --- |
| 排产策略 | `新增` | 弹出策略编辑框 | 是否定义了方向、时间、规则 | 保存并启用 |
| 排产策略 | 有效开关 | 当前行变为有效 | 本次排产是否应使用该策略 | 去排产计划 |
| 排产计划顶部卡片 | 点击 `生成排产` | 打开策略选择弹窗 | 是否已具备排产前置数据 | 选策略后发起 |
| 排产进度 | `详情>` | 打开进度明细 | 看日志与状态 | 决定预览、放弃或重试 |
| 排产进度 | `预览` | 打开全屏预览 | 计划是否可执行 | 必要时去甘特图调整 |
| 资源甘特图 | `移动` | 打开移动操作 | 是否只是局部冲突 | 移动后再复核 |
| 资源甘特图 | `锁定` | 任务锁定 | 是否必须固化该任务 | 确认前保留 |
| 资源甘特图 | `派工` | 导出派工结果 | 是否可以下发现场 | 进入执行 |
| 资源甘特图 | `报工` | 打开报工入口 | 实际进度是否需要回写 | 更新完成数据 |
| 排产进度 | `提交` | 确认正式计划 | 锁定策略是否已经正确使用 | 计划生效 |
| 排产进度 | `放弃` | 丢弃本次排产结果 | 当前结果是否不可接受 | 回到数据修正或重跑 |

## 7. 异常结果处理表

| 现象 | 第一判断 | 你先去哪一页 | 你自己能不能修 | 正确处理 |
| --- | --- | --- | --- | --- |
| 排产失败 `FAILURE` | 可能是主数据缺失、约束冲突或服务异常 | 先看排产进度明细，再查订单/BOM/工艺路线/日历 | 通常能修业务数据，不能修代码异常 | 先修数据；若后端报错，转开发 |
| 排产成功但大量订单仍未排 | 可能订单不可排、交期冲突、资源不足 | `待排订单`、`生产日历`、`工艺路线` | 部分能修 | 先看 `canSchedule`、资源班次、路线是否启用 |
| 甘特图任务碎片过多 | 可能策略排序不合理或人工拆分过度 | `排产策略`、`资源甘特图` | 能修 | 优先改策略；不要长期靠人工合并兜底 |
| 物料需求看起来不对 | BOM 或来料计划不可信 | `制造BOM`、`来料计划` | 能修 | 先修输入，不要直接确认计划 |
| 某关键任务时间必须固定 | 现场约束高于求解器结果 | `资源甘特图` | 能修 | 移动后立即锁定 |
| 现场说计划不现实，但系统看起来“没报错” | 这是结果质量问题，不是技术成功问题 | `资源甘特图`、`订单甘特图`、`策略` | 能修一部分 | 复盘策略、日历、工艺节拍；必要时重排 |
| 想导入工艺路线 Excel | 当前产品没这个入口 | 无对应页面 | 不能 | 转实施/开发评估批量导入能力 |

## 8. 什么时候该转办

| 问题类型 | 转给谁 |
| --- | --- |
| 工艺、工艺路线、BOM、资源、日历缺失或错误 | 主数据维护责任人或你自己修 |
| 排产规则不合理，需要更改策略 | 你自己修 |
| 现场已开工，需要根据实际进度回写 | 排产员或生产调度员处理 |
| 需要批量导入基础数据 | 实施/开发 |
| 排产接口报错、页面异常、权限不对 | 开发/实施 |

## 9. 当前版本边界

1. 当前版本没有通用主数据 Excel 批量导入中心。
2. 当前版本有角色权限，但不是所有页面按钮都做到了最细粒度业务隔离，所以你要按岗位流程使用，不要拿“看得到”当成“应该做”。
3. 当前版本的正式计划确认，是通过“确认排产结果”完成，不是多版本会签流。
4. 当前版本支持操作审计，但不等于替代业务审批。

如果你只记一句话，请记这句：**计划主管的核心价值不是“点一下排产”，而是用正确数据、正确策略、正确确认动作，把一版可以执行且可追责的计划交付出去。**
