# 生产调度员端到端傻瓜式操作手册

适用角色：`APS_DISPATCHER`

你不是排产策略制定者，也不是正式计划确认人。当前版本里，你的核心职责是：**看正式计划、把任务派下去、把现场真实进度收回来、把异常及时往上游反馈。**

## 1. 你今天要完成什么

1. 查看已经确认的计划结果。
2. 按资源与任务节奏进行派工。
3. 根据现场反馈录入或导入报工。
4. 发现不合理计划时，及时反馈给排产员或计划主管。

## 2. 你能看到哪些菜单，不能做什么

你能看到：

| 菜单 | 你能做什么 |
| --- | --- |
| 物料、主资源、生产订单、来料计划、制造BOM、工艺、工艺路线、生产日历 | 只读查看，用于理解任务背景 |
| 排产计划 | 查看正式计划结果、派工、报工 |

你通常不应该做，也基本做不了：

| 事项 | 原因 |
| --- | --- |
| 发起排产 | 没有 `aps:schedule:run` |
| 预览候选排产 | 没有 `aps:schedule:preview` |
| 确认或放弃排产 | 没有 `aps:schedule:confirm`、`aps:schedule:cancel` |
| 调整任务拆分、合并、移动、锁定 | 没有 `aps:task-adjust:edit` |
| 查看排产策略 | 没有 `aps:strategy:view` |

你真正可用的强项是：

| 动作 | 是否可用 |
| --- | --- |
| `派工` | 可用 |
| `报工` | 可用 |
| 在任务详情里修改 `实际完工时间`、`实际完成数量` | 可用 |

## 3. 先记住四条现场原则

### 3.1 你处理的是“执行偏差”，不是“排产逻辑”

现场反馈的完成数量、完成时间、异常停机，这些是你的处理对象。  
如果根因是工艺路线不对、资源班次不对、订单优先级不对，这不是靠你改报工能解决的。

### 3.2 系统里的正式计划，才是你今天的作业底稿

你看的是已确认计划，不是预览结果。你要避免拿候选版本去指挥现场。

### 3.3 先如实反馈，再讨论计划是否要重排

现场实际完工时间和数量要先回写，别为了“看起来计划没偏差”而晚填或不填。没有真实进度，后续任何重排都不可信。

### 3.4 当前版本没有给你工艺路线 Excel 导入

你如果发现现场工艺和系统不一致，不能自己导入一份 Excel 修路线。正确动作是记录差异并转给计划主管/主数据维护人。

## 4. 每天上班第一步怎么点

1. 打开 `排产计划`
2. 默认先看 `资源甘特图`
3. 找到今天本班组、本设备、本产线要执行的任务
4. 核对任务开始时间、结束时间、数量、工序
5. 必要时切到 `计划任务` 查单个任务详情

你要先确认“今天做什么”，而不是一上来就改数据。

## 5. 标准端到端流程

## 5.1 第一步：看正式计划

页面：`排产计划` -> `资源甘特图`

你要看四件事：

| 关注点 | 为什么重要 |
| --- | --- |
| 任务开始/结束时间 | 决定班组什么时候开工、切换、收工 |
| 计划主资源 | 决定在哪台设备或哪条资源上执行 |
| 任务数量 | 决定领料、备工装、派班人数 |
| 工序信息 | 决定现场执行内容是否匹配 |

如果现场说“今天不可能按这个顺序做”，你先不要自己改任务顺序，因为你没有这个权限，而且这属于排产侧问题。

## 5.2 第二步：派工

页面：`资源甘特图`

操作：

1. 在资源甘特图找到今天要执行的任务
2. 点击 `派工`
3. 导出或下发派工结果
4. 将派工单、任务列表或对应信息交给现场班组

结果判断：

| 结果 | 说明 | 下一步 |
| --- | --- | --- |
| 派工成功 | 今日执行任务已下发 | 跟踪开工与完工反馈 |
| 现场无法接单 | 正式计划与现场约束冲突 | 立即反馈排产员或计划主管 |

## 5.3 第三步：报工

页面：`资源甘特图`

操作：

1. 现场回报某任务已完工或部分完工
2. 点击 `报工`
3. 按系统要求导入报工数据，或进入任务详情手工填写
4. 更新 `实际完工时间`
5. 更新 `实际完成数量`
6. 保存

为什么一定要做这一步：

- 下一轮排产是否可信，取决于系统是否知道哪些任务已经做完、做了多少。
- 如果你只口头反馈，不回系统，计划侧看到的仍是假数据。

## 5.4 第四步：修改单个任务的完成信息

页面：`资源甘特图` -> 任务详情

打开任务详情后，你能看到：

| 区块 | 你可以做什么 |
| --- | --- |
| 基本信息 | 看任务编码、订单、产品、工序 |
| 计划信息 | 看计划时间、计划资源、计划工时 |
| 实际信息 | 修改 `实际完工时间`、`实际完成数量` |
| 子任务 | 合并任务场景下，对子任务逐条维护实际进度 |

标准填写规则：

1. 如果任务已经全部完成，就填真实完工时刻和真实完成数量。
2. 如果只做了一部分，就填当前累计完成数量。
3. 如果是合并任务，优先在 `子任务` 维度维护，避免总量对了、子任务错了。

## 5.5 第五步：发现异常时怎么反馈

你看到异常后，不是所有问题都应该自己改。

### 你可以自己处理的异常

| 异常 | 你怎么处理 |
| --- | --- |
| 完工时间填错 | 直接进任务详情修正 |
| 完成数量填错 | 直接进任务详情修正 |
| 同一合并任务下某子任务进度没回写 | 打开 `子任务` 页签分别修正 |

### 你应该立即上报的异常

| 异常 | 转给谁 | 原因 |
| --- | --- | --- |
| 正式计划顺序不合理 | 排产员 | 需要调整任务顺序或局部重排 |
| 资源/设备今日停机，计划无法执行 | 排产员或计划主管 | 需要重新调整时间或资源 |
| 工艺路线与现场真实做法不一致 | 计划主管/主数据维护人 | 根因在主数据 |
| 订单优先级明显不对 | 计划主管 | 根因在业务决策 |
| 想批量导入工艺路线、BOM、日历 | 实施/开发 | 当前产品无此入口 |

## 6. 按钮级操作对照表

| 页面 | 按钮/动作 | 你会看到什么 | 说明什么 | 下一步 |
| --- | --- | --- | --- | --- |
| 资源甘特图 | `派工` | 成功提示或导出结果 | 正式计划可下发执行 | 现场开工 |
| 资源甘特图 | `报工` | 打开报工入口 | 可以回写现场进度 | 填写真实数据 |
| 任务详情 | 修改 `实际完工时间` | 时间字段可编辑 | 系统允许修正完成时刻 | 保存后复核 |
| 任务详情 | 修改 `实际完成数量` | 数量字段可编辑 | 系统允许修正完成量 | 保存后复核 |
| 子任务页签 | 分别填写子任务数据 | 每条子任务可单独维护 | 合并任务也能精确回写 | 保存并通知上游 |

## 7. 常见问题处理表

| 现象 | 先判断什么 | 你能否自己解决 | 正确动作 |
| --- | --- | --- | --- |
| 现场说排的时间做不到 | 是执行偏差还是计划错误 | 不能直接改顺序 | 先派工暂停，反馈排产员 |
| 任务已完成但系统还显示未完成 | 是否未报工 | 能 | 立即报工或补录任务详情 |
| 完成数量少于计划 | 是正常偏差还是物料/设备异常 | 只能回写真相，不能自改计划 | 先录实际数量，再上报原因 |
| 某工序现场根本不这么做 | 工艺路线与现场不一致 | 不能 | 转主数据维护人 |
| 希望直接导入工艺路线 Excel | 当前产品是否支持 | 不能 | 转实施/开发 |

## 8. 当前版本边界

1. 你看到的是正式计划结果，不是排产试算环境。
2. 你可以反馈执行事实，但不能替代排产员做任务顺序调整。
3. 你可以修实际完成信息，但不能修主数据逻辑问题。
4. 当前版本没有面向调度员的主数据批量导入能力。

如果你只记一句话，请记这句：**生产调度员最重要的不是“把计划讲给现场听”，而是把现场真实执行结果及时、准确地回写进系统，并在计划失真时第一时间向上游发出信号。**
