# 数字孪生 · 排程价值的阅读路径与关联路径

`digital-twin-demo` 作为排产系统能力并入 `aps-ui`（左侧「生产计划 → 数字孪生」）的设计与实现记录。
版本：2026-11-28（第三版：接入当前租户真实数据 + 自适应布局 + 来料节点展开）。读者：前端实现者、售前/演示、计划主任（评审用）。

---

## 0 摘要

数字孪生不是三维动画，是把排产算法在车间本体里**做的事**变成可看见、可点开、可验证的画面。本版做了四件事：

1. **真实数据**：新增聚合端点 `GET /digital-twin/snapshot`，一次取齐当前租户的资源台账、订单、已确认计划、候选计划、在途来料、物料库存与每道工序的物料投入。孪生页面在快照注入前**不渲染任何演示内容**；没有计划就如实显示空态。
2. **三维绑定真实设备**：8 个工位是示意几何，落在工位上的设备、名称、提示、原料堆、半成品缓冲、成品库和管线全部来自租户数据；管线按真实工艺链生成。
3. **自适应布局**：面板迁出 1920×1080 的缩放舞台，改为视口级 CSS Grid；三维场景自动让开左栏并缩放到整厂可见；1024～1920 宽、720～1080 高实测无重叠、无溢出。
4. **来料节点展开**：点时间线上的到货点，回答「这批料是什么、何时到、够不够、被哪些工序消耗、开工时料到位了没有」——这是「齐套门禁 · 到货即排」在真实数据上的证据。

## 1 数据链路

| 孪生需要 | 来源（服务端 `DigitalTwinSnapshotService.snapshot()`） | 口径 |
| --- | --- | --- |
| 设备台账 | `jvs_production_resource` | id / 编码 / 名称 / 分组 / 产能 / 节拍 / 状态 |
| 订单 | `jvs_production_order`（排除已完成、已取消） | 含补充订单，带父订单编码 |
| 已确认计划 | `jvs_plan_task` | 任务带 **物料投入** `input_materials`（物料 id → 编码） |
| 候选计划 | `jvs_plan_task_pending`；没有待确认计划时取最近一次 `FEASIBLE` 求解审计 | `candidateSource = PENDING / AUDIT`，界面如实标注「待确认 / 最近一次求解」 |
| 来料计划 | `jvs_incoming_material_order`（在途） | 逐批：编码 / 物料 / 数量 / 预计到货 |
| 物料台账 | `jvs_material` | 库存 / 安全库存 / 计量单位（只带来料或工序投入涉及的物料） |

KPI 与三类决策的数字在服务端算好（与求解审计同源），孪生只负责呈现：

| 指标 | 口径 |
| --- | --- |
| 排入订单 / 未排订单 | 按**主订单**计（补充订单由主订单 MRP 生成，不单独算） |
| 逾期分钟 | 主订单**末道工序**完成晚于交期的分钟数之和 |
| 换型次数 | 任一设备上相邻任务的产品不同的次数 |
| 负载离散 | 各设备占用分钟的标准差 |
| 决策对比 | 有候选 → 「当前 → 候选」；没有候选 → 只给当前计划的数字，不编造对比 |

**诚实规则**

- 改善绿 / 持平灰 / 恶化红：只比较，不替数据说好话（当前租户的候选逾期 45291 → 45372 就标红）。
- 真实态里不出现演示文案：设备详情只陈述台账事实与计划队列；「此刻在做什么」标注为**计划推演**，不冒充 MES 报工。
- 独立打开 `digital-twin/index.html` 仍是演示数据，头部明示「**演示数据** · 推演 …」。
- 落不到三维工位的设备记为「未建模」，宿主页提示「仅见于甘特」。

### 1.1 设备 → 工位绑定（`sim.bindStations`）

三步落位，都对不上就是未建模：

1. 资源编码 = 工位编码（e2e 种子即按此车间建模：`QG1…CS1`）；
2. 分组 / 名称 / 工序编码命中工位关键字（切割、焊接、喷涂、总装、测试…）；
3. 其余设备按各自在订单工艺链中的平均序位，顺工艺流填入空工位。

管线由两版计划的真实工艺链生成：首道工序从原料区进料；补充订单的末道工序进半成品缓冲，缓冲再进主订单首道工序；没有下游的工序进成品库。

## 2 阅读路径（真实态，自上而下）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [当前计划|优化候选]  6→6 排入  0→0 未排  45291→45372 逾期     ↗ ⛶          │ ① 切的是整套排程解
│ [齐套门禁 0→0] [换型归并 5→5] [负载均衡 0%]                               │ ② 算法做了什么 → 点它
│ 当前租户实时数据 · 36 项已确认任务 · 候选 36 项（待确认）· 时间   [刷新]     │    数据来源如实标注
├──────────────────────────────────────────────────────────────────────────┤
│ ERP ● 实时快照 13:45:26 │ 2026/11/28 13:45:55 │ 计划推演 12/03 08:57     │ ③ 当前时刻 vs 推演时刻
│ 工件（订单）■SYN-FL-001 … ■SYN-FL-006                                    │
│ ┌排产决策──────┐                                                         │ ④ 证据明细（当前选中决策）
│ │ 证据行…      │              三 维 车 间                                │
│ ├排程计划──────┤   原料区 → 工位（真实设备名）→ 缓冲 → 成品               │ ⑤ 本体
│ │ 8 泳道甘特   │   管线按真实工艺链；设备灯 / 物料流按推演时刻            │
│ └──────────────┘                                                         │
│ ●──●──●──●──●  来料计划 · 在途到货   当前│        │开工 │推演            │ ⑥ 点到货点展开
└──────────────────────────────────────────────────────────────────────────┘
```

| 层 | 回答哪个问题 | 点下去发生什么 |
| --- | --- | --- |
| ① 计划切换 | 换个计划，结果差多少 | 甘特整表换版；证据面板标注「已确认计划 / 优化候选 vs 已确认计划」 |
| ② 决策卡 | 算法凭什么做到 | 镜头飞到证据涉及的工段（同一工段飞近，跨工段回全景）；相关设备高亮；证据明细切换 |
| ③ 头部 | 画面上的时间是现在吗 | 墙上时钟 = 当前时刻；「计划推演」= 虚拟时钟沿计划时间轴回放（6 分钟 / 秒） |
| ⑤ 三维 | 这台设备在干什么 | 点工位 → 设备台账 + 推演中任务 + 本设备排程队列；点原料堆 → 来料展开（见第 3 节） |
| ⑤ 甘特 | 这根条是什么 | 点条 → 任务详情（工件 → 工序 → 流水线、时间窗、交期结论）；泳道与三维工位联动 |
| ⑥ 来料时间线 | 料什么时候到、卡不卡开工 | 点到货点 → 来料展开（见第 3 节） |

## 3 来料节点展开（到货 → 齐套 → 开工）

来料时间线上每个 ● 是**一批在途来料**（同一物料多批是多个点）。点它（或点三维里对应的原料堆）在左栏展开三段信息，同时甘特上**消耗该物料的工序高亮**、时间线节点选中、三维原料堆点亮：

| 段 | 内容 | 数据 |
| --- | --- | --- |
| 来料计划 | 来料单号、物料、本批数量、预计到货、相对计划开工（前 / 后多久）、相对当前（多久后到货 / 已过预计时刻仍在途） | `jvs_incoming_material_order` |
| 物料供需 | 库存 / 安全库存、在途合计（几批）、计划消耗（几道工序）、其他批次 | `jvs_material` + 任务投入 |
| 消耗该物料的工序 | 按开工排序列出：订单 · 工序 · 开工时刻 · 与本批的关系；点一行钻到该工序的任务详情 | 当前计划 / 优化候选的 `input_materials` |

**每道工序相对本批的四种关系**（按时间逐笔对账：库存 + 到货 − 消耗）：

| 标记 | 含义 | 颜色 |
| --- | --- | --- |
| 到货后 | 本批到货之后开工，开工时料已到位 | 绿 |
| 靠库存 | 本批到货之前开工，由库存 / 更早批次支撑 | 琥珀 |
| 待后续批 | 只算到本批（含库存）不够本工序用，实际开工还依赖更晚的批次 | 琥珀 |
| 缺 N | 开工时库存 + 已到货不足以覆盖本工序需求 | 红 |

**当前租户的实例**（e2e 种子，6 单 8 设备）

| 到货点 | 展开结论 |
| --- | --- |
| 静音轮系轴承 500 个 · 12-03 09:00（IMO-E2E-LATE） | 库存 0 / 安全 200；在途 520（2 批）；6 道总装全部「到货后」开工，首个总装 12-03 14:33 → 这批料把总装压在计划开工后 1 小时 |
| 静音轮系轴承 20 个 · 11-28 09:00（IMO-E2E-ONTIME） | 同样 6 道总装全部「待后续批次」——20 个不够，实际在等上面那批 |
| 冷轧钢板 / 环氧粉末 / 合成液压关键件 | 库存充足，对应的 6 道切割 / 喷涂 / 液压预装全部「到货后」 |

「齐套门禁」卡在没有未排订单时，证据行取自这里：`物料 · 到货时刻 → 首个消耗工序 设备 开工时刻`。

**演示态**（独立打开）没有工序级投入数据，按演示设定展开：物料、在途、库存、相对推演时刻、到货后解锁的订单及其候选最早开工。

## 4 关联路径（本体 → 算法）

```
来料到货点(时间线●) ──展开──▶ 物料供需 ──对账──▶ 消耗工序(甘特高亮) ──▶ 任务详情 ──▶ 三维工位
                                      │
                              齐套门禁卡（到货 → 首个消耗工序开工）
                                      │
        换型归并卡 ──▶ 设备换型证据 ──▶ 工段近景        负载均衡卡 ──▶ 各设备负载 ──▶ 全景
```

| 操作 | 画面反馈 | 实现 |
| --- | --- | --- |
| 宿主页点决策卡 | 飞到证据涉及的工段；设备高亮；甘特泳道高亮；证据明细切换 | `twin:decision` → `focusDecision(key)` |
| 宿主页切计划版本 | 甘特换版；证据面板标注；KPI 与决策摘要回传宿主页 | `twin:plan` → ack 带 `kpi` + `decisions` |
| 点时间线到货点 / 三维原料堆 | 来料展开；消耗工序高亮；原料堆点亮；节点选中 | `focusSupply(material)` |
| 点来料展开里的工序行 | 该工序的任务详情；飞到所在工位；工位高亮 | `#plan-detail` 委托 `.dt-row[data-task]` |
| 点甘特条 | 任务详情（只占证据区，甘特保持可见）；飞到工位 | `.gbar` click |
| 点三维工位 | 设备台账 + 推演 + 排程队列（占满左栏） | `engine.onClick` |
| 关闭（✕ 或点场景空白） | 明细关闭；来料高亮、泳道选中一并清掉 | `closeDetail()` |

## 5 自适应布局

- 面板在视口级 `#ui`（CSS Grid）里按真实像素排布，与 `#stage`（1920×1080 等比缩放的三维舞台）完全解耦。
- 列：`minmax(240px,320px) 1fr minmax(240px,280px)`；行：头部 / 图例 / 主体 / 来料时间线。
- 断点：≤1360px 隐藏导航项与状态图例；≤980px 单列堆叠（三维在面板之间可见）；≤620px 高压缩左栏。
- 三维全景自动适配：场景右移半个左栏并缩放，使整厂落在「左栏以外的可见区」内；停在全景时窗口变化跟着重新取景，在近景时只改投影偏移。
- 甘特面板按泳道数撑高（多设备时内部滚动）；任务 / 来料明细按内容撑高：≥900px 高时落在证据区、甘特保持可见；720px 高时左栏放不下，明细占满左栏（甘特被盖住，点工序行可钻到任务与工位）。

实测（无面板重叠、无内容溢出、8 泳道全可见）：1920×1080、1600×900、1440×810、1366×768、1280×720、1100×700、1024×768；窄屏 980×700、900×1000、760×900 单列堆叠无重叠。

## 7 已知边界与后续

- **工位几何是示意**：三维里是 8 个通用机床工位，超过 8 台设备时多出的记为未建模（只在甘特里）；管线只表达工序先后，不表达 BOM 级「哪种料进哪道工序」以外的物流。
- **未排原因**：未排订单的原因（缺哪种料、缺口多少）由 MRP 欠料结果给出，该结果在 `feature/shortage-alerting` 分支，尚未合入 `main`；合入后「齐套门禁」卡的证据行可直接取缺口明细。
- **候选来源**：没有待确认计划时候选取最近一次求解审计，界面标注「最近一次求解」；审计不存物料投入时，消耗工序从已确认的同编码任务回查。
- **工作日历**：甘特条按自然时间画，未叠加班次 / 停机窗底纹。
- **演示种子自相矛盾**（仅演示态）：演示设定 PO-005 / 006 被轴承 / 铜线「到货后解锁」，但演示候选计划里它们的切割在到货前就开工；真实数据（当前租户）的对账是一致的。是否修正演示时间，待定。
