# MRP 在途库存修复验收

日期：2026-11-17。

本次修复在途来料的时间判断和物料查找键，沿用现有订单交期作为可用截止点：

```text
来料可用时间 = 预计到货时间 + 物料缓冲期
来料可用时间 <= 订单交期：可以分配
来料可用时间 > 订单交期：保留该批来料，缺口继续进入 MRP
```

原代码把早于交期可用的来料跳过，同时允许延期来料抵扣需求；此外，基础数据按物料 ID 分组，扣减逻辑却按物料编码查询。现统一按 ID 查询，并明确检查缓冲后的可用时间。现有库存优先、按到货时间分配、剩余数量留给后续订单的处理保持原有语义。

**专项验证**

`InventoryUtilsTest` 覆盖 10 项：提前到货、恰好在交期到货、延期到货、缓冲期导致超期、缓冲期结束恰好等于交期、部分到货、按到货顺序分配并保留余量、跨订单防重复占用、现有库存优先，以及没有来料时的缺料计算。测试的物料 ID 与编码不同，防止查找键错误被掩盖。

`MrpSchedulingTest` 通过实际的 MRP、生产任务生成和求解器调用链验证以下场景。每个场景均运行 OptaPlanner / Timefold × 正排 / 倒排，共 12 次求解，检查完整分配、零硬约束、资源不重叠和子件先于装配完成。

| 场景 | 订单与 BOM | 子件供给 | 子件计划生产量 |
| --- | --- | --- | --- |
| 提前到货 | 5 件成品，每件用 2 件子件 | 提前来料 10 件 | 0，避免重复补产 |
| 延期到货 | 同上 | 交期之后来料 10 件 | 10，延期来料不抵扣 |
| 部分到货 | 同上 | 现存 3 件、提前 4 件、延期 10 件 | 3，仅补净缺口 |

另验证关闭“约束物料”后仍跳过 BOM 和库存分配，不改变现有开关语义。

**回归与复现**

修复前新增库存测试有 6 项失败，修复后专项 14 项通过。完整后端 `mvn clean verify` 共 53 项通过，包含原有 39 项回归，覆盖双引擎、正倒排、冻结任务、动态约束、FULL_ASSERT、快照回放、取消和模型协议。

在 Java 17 环境下，从 `aps` 目录执行：

```bash
mvn -pl jvs-aps-common -am -Dtest=InventoryUtilsTest,MrpSchedulingTest -Dsurefire.failIfNoSpecifiedTests=false test
mvn clean verify
```

本次不涉及数据库迁移或接口变更。曾经漏用提前来料或误用延期来料的场景，其净需求和补产数量会按上述规则纠正。
