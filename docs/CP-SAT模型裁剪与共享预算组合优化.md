# CP-SAT 模型裁剪与共享预算组合优化

## 实现顺序与安全边界

本轮按“等价简化 → 安全收紧 → 组合精修 → 参数对照”的顺序实现。模型简化默认启用；组合求解默认关闭，可按策略开启。部署必须同时更新主服务和 worker：通信协议升级为 v3，混用版本会被拒绝。

### 1. 按业务配置省略邻接模型

每台设备始终保留 `NoOverlap` 资源互斥。只有换型成本非零，或该设备候选非冻结任务存在非零准备间隔时，才建立排序 circuit。零换型权重、零准备间隔时不再建立二次规模的相邻关系变量。

优先级逆序成本单独建模，不随 circuit 一并删除；负载、交期、工序等待、完工时间等原有成本保持一致。带准备间隔或换型成本的场景仍保留完整邻接模型，不能以性能为由省略约束。

### 2. 收紧时间域与裁剪日历分段

`TimeDomains` 从释放时间、计划窗口、冻结任务、局部优化范围外已固定任务、候选设备日历以及 ES/EE 工序关系传播上下界。每个候选设备的日历分段与传播后的时间域求交，无交集的分段不建布尔变量。

多设备、多分段使用所有可能区间的包络，不能只保留当前设备或最短工时设备。传播迭代上限只影响收紧程度；提前终止不会排除合法方案。交期不是硬上界，也不以启发式方案的完工时间裁掉允许逾期但目标更优的方案。

### 3. Timefold 热启动与瓶颈局部精修

开启 `cpSat.timefoldWarmStart` 后：

1. 先独立验证现有计划。已有完整可行基线时直接进入局部精修，不重复生成种子。
2. 无有效基线时，复制求解快照，创建独立 Timefold 求解器；不会替换租户 SolverManager。冻结任务保留，其他任务重新构造。
3. Timefold 种子必须再次经过 CP-SAT 协议的完整可行性校验。只满足 Timefold 分数而未通过统一口径的方案不会被当作可行基线。
4. 从显式任务种子或最严重逾期末工序（无逾期时选择最晚完工任务）出发，按工序关系与同设备前后任务扩展有界邻域。邻域外任务的设备、开工和完工全部固定。
5. CP-SAT 使用种子提示、基线目标上界和剩余时间进行精修。有剩余预算时逐轮增加邻接深度（最多五层），与前一轮范围取并集，始终保留统一目标最好的可行方案；达到邻域任务上限或总截止时间便停止。每轮独立校验并记录实际范围、状态、模型规模与 CPU。新生成、尚未发布的种子不收取生产调整成本；已确认基线继续使用调整成本和方案采用门槛。
6. 预算耗尽且有已验证基线时保留基线；无可行解时失败关闭，不生成非法待确认计划。取消不会触发保留基线发布。

时间预算从 CP-SAT 引擎入口开始，覆盖映射、Timefold、worker 启动、建模和搜索。父进程另留 1 秒协议收尾宽限；数据库、HTTP 轮询与后处理另计，因此 HTTP 耗时不能等同于求解时间。组合求解不是两个各自完整预算的串行求解。

### 4. 搜索参数与计算成本

| 策略字段 | 默认值 | 含义 |
|---|---|---|
| `timefoldWarmStart` | `false` | 开启共享预算组合求解 |
| `sizeAwareBudget` | `true` | 按任务规模选择种子预算比例 |
| `timefoldBudgetPercent` | `50` | 关闭规模分配时使用，允许 10–80 |
| `searchMode` | `AUTOMATIC` | 可选 `PORTFOLIO`，不承诺更优 |
| `numWorkers` | `1` | 允许 1–8，受服务全局 CPU 配额约束 |
| `neighborhoodDepth` | `1` | 工序和设备邻接扩展层数 |
| `maxNeighborhoodTasks` | `60` | 超出上限明确拒绝，禁止悄悄扩大范围 |

规模分配：不超过 24 道工序给 Timefold 剩余预算的 30%，25–48 道为 40%，更大规模为 60%。这是可配置的起始策略，并非对所有业务数据证明最优的比例。

审计新增模型变量/约束数、circuit 数、裁剪前后日历分段数、worker CPU 毫秒、种子阶段 CPU/墙钟耗时、实际局部任务数与共享预算。worker CPU 为原生加载、建模、搜索阶段同一进程两次累计 CPU 读数之差（另记录父进程可读取时的请求全程 CPU）；平台不支持时为空，不以墙钟时间冒充 CPU。Timefold CPU 只计种子求解线程，不包含 JVM GC 等其他线程。HTTP 脚本还可通过 `--backend-pid` 采集主 JVM 全进程 CPU（包含 GC 与其他服务线程），不与种子线程 CPU 重复相加。多轮 worker CPU 累加；超时强杀无法读取最后一轮时标记 `workerCpuComplete=false`，不得当作完整 CPU 总成本。

## 验证与复现

回归包含有无换型成本、有无准备间隔的新旧模型最优成本对照，以及跨休息日历、ES/EE 依赖下枚举合法解不被时间传播排除的检查。基线保护、取消、模型缓存、毫秒精度、物料与应用日历复核仍使用原有校验链。

HTTP 对照脚本：`aps/scripts/e2e_cpsat_search.py`。只允许运行在专用 `aps-ade-e2e-mysql` 的 `aps_e2e` 数据库，执行会重置该隔离库的 demo 排程数据。

```bash
python3 aps/scripts/e2e_cpsat_search.py --disposable --orders 4 8 12 --seeds 17 29 43 --seconds 30 --backend-pid <隔离后端PID>
# 已有结果上补充线程与搜索方式实验
python3 aps/scripts/e2e_cpsat_search.py --disposable --resume --orders 4 8 12 --seeds 17 --modes PORTFOLIO TWO_WORKERS --seconds 30
```

比较自适应 Timefold（SCALE_AWARE）、独立 CP-SAT 与共享预算组合求解。每组校验相同业务输入指纹；统一记录可行性、六项业务成本、逾期分钟、实际耗时、模型规模和 CPU。局部最优只对固定邻域成立，不能解读为全局最优。对照结果见 [本轮验收记录](e2e/cpsat-search/README.md)。
